# Binary Parser

Программа для генерации и парсинга бинарных `.dat`-файлов с данными тренировочного плана.

Проект состоит из двух частей:

- **DatGenerator** — создаёт бинарный файл с данными тренировочного плана.
- **TrainingViewer** — считывает созданный бинарный файл, отображает данные в графическом интерфейсе, позволяет их редактировать и сохранять.

В тренировочном плане используются 3 упражнения:

- подтягивания;
- отжимания;
- приседания.

Количество тренировочных дней может быть от 1 до 7.

## О проекте

Изначально задача парсинга бинарного файла появилась у меня на работе. Была известна структура файла, описанная словами, и требовалось научиться:

- считывать данные из бинарного файла;
- изменять их;
- сохранять изменённые данные в новый бинарный файл;
- сохранять данные в формате `.csv`.

В этом проекте я хотел сохранить общий алгоритм обработки бинарного файла, но убрать рабочую информацию.

Заодно проект стал практикой работы с:

- битовыми полями;
- `bitset`;
- JSON;
- бинарными файлами;
- графическим интерфейсом Qt;
- сохранением данных в `.csv`.

Рабочая информация была удалена, а вместо неё использована тема тренировок. В результате получился пример бинарного формата с тренировочным планом на 1–7 дней.

## Структура проекта

В репозитории находятся два отдельных проекта:

```text
binary-parser/
├── DatGenerator/
│   └── ...
│
├── TrainingViewer/
│   └── ...
│
└── README.md
```

### DatGenerator

`DatGenerator` отвечает за создание бинарного файла.

Перед запуском пользователь указывает количество тренировочных дней от 1 до 7. После этого программа создаёт соответствующий `.dat`-файл.

Например:

```text
TrainingWeek1.dat
```

Созданный файл затем используется программой `TrainingViewer`.

### TrainingViewer

`TrainingViewer` — графическая программа для просмотра и редактирования созданного бинарного файла.

В программе можно:

- выбрать режим тренировок;
- открыть бинарный файл;
- просмотреть данные в таблице;
- изменить значения;
- сохранить данные в новый бинарный файл;
- сохранить данные в формате `.csv`.

## Использование

### 1. Создание бинарного файла

Сначала необходимо создать бинарный файл с помощью проекта `DatGenerator`.

Откройте проект `DatGenerator` в Qt Creator.

При первом открытии проекта в Linux Qt Creator может открыть окно настройки проекта. В нём необходимо выбрать компилятор и другие параметры сборки.

Для запуска программы через терминал:

1. Откройте настройки запуска проекта.
2. Перейдите в раздел **«Сборка и запуск»**.
3. Откройте вкладку **«Запустить»**.
4. В центральной области настроек включите **«Запускать в терминале»**.

После запуска `DatGenerator` введите в консоли количество тренировочных дней — от 1 до 7 включительно.

Например:

```text
3
```

После нажатия `Enter` программа создаст бинарный файл.

В папке проекта, внутри папки сборки, название которой начинается с `build`, появится файл вида:

```text
TrainingWeek1.dat
```

### 2. Открытие бинарного файла

После создания файла запустите проект `TrainingViewer`.

В программе сначала необходимо выбрать режим тренировок с помощью кнопки **«Выбрать режим»**.

Количество выбранных дней должно соответствовать количеству дней, которое было указано при создании файла в `DatGenerator`.

После этого нажмите **«Открыть файл»** и выберите созданный ранее `.dat`-файл.

После успешного открытия данные тренировок появятся в таблице.

### 3. Редактирование данных

Значения в таблице можно редактировать.

Для этого необходимо нажать правой кнопкой мыши по нужной ячейке и выбрать соответствующее действие в контекстном меню.

В таблице отображаются:

- первые три столбца — прогресс или регресс по трём упражнениям;
- следующий столбец — относительная тяжесть тренировки по сравнению с предыдущей;
- остальные столбцы — абсолютные значения для упражнений в конкретный день тренировки.

### 4. Сохранение данных

После редактирования данные можно сохранить:

- в новый бинарный файл;
- в файл `.csv`.

## Как устроены данные

Одной из целей проекта было сохранить алгоритм работы с бинарными данными, поэтому часть информации хранится не в обычном виде, а в битовых полях.

### JSON

JSON используется для хранения режимов тренировок.

В нём находится массив режимов тренировок в неделю. Каждый режим содержит название и список дней, относящихся к этому режиму.

Условно структура выглядит следующим образом:

```json
[
    {
        "Режим": "1 р/нед",
        "Дни": [
            "1 день"
        ]
    },
    {
        "Режим": "2 р/нед",
        "Дни": [
            "1 день",
            "2 день"
        ]
    }
]
```

При выборе режима в графическом интерфейсе программа находит в JSON соответствующий режим и получает из него список тренировочных дней.

Таким образом, количество и названия отображаемых дней зависят от выбранного режима.

### Бинарный файл

Для хранения некоторых данных используется 16-битное слово.

Оно состоит из четырёх полей:

```text
┌─────────┬─────────┬─────────┬───────┐
│ 5 бит   │ 5 бит   │ 5 бит   │ 1 бит │
└─────────┴─────────┴─────────┴───────┘
     ↓         ↓         ↓        ↓
 упражнение  упражнение  упражнение  параметр
```

Итого:

```text
5 + 5 + 5 + 1 = 16 бит
```

Три первых столбца таблицы соответствуют трём пятибитным полям этого 16-битного слова.

Благодаря тому, что каждое из этих значений занимает 5 бит, его диапазон ограничен количеством доступных битов.

Четвёртое поле занимает 1 бит и используется для хранения булевого значения относительной сложности текущей тренировки по сравнению с предыдущим днем тренировки.

Такой способ хранения данных позволяет на практике работать с отдельными битовыми полями внутри бинарной структуры.

- сохранение данных в бинарном и текстовом форматах.
